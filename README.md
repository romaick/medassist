# МедАссистент

Поликлинический офлайн-прототип для Windows: структурированный приём, анамнез, осмотр и редактируемый черновик врачебной записи. Версия 0.9.0.

В 0.9.0 пустая новая форма не создаёт карточку. «Начать приём» открывает поиск существующего пациента; «Новый пациент» открывает пустую форму. Карточка и первый приём сохраняются после первого содержательного ввода: ФИО, сведений приёма, изменённой даты, текста записи или применения шаблона осмотра. Переходы между разделами и пробелы ничего не сохраняют. После первого сохранения очистка полей не удаляет приём. Прежние карточки остаются без изменений.

Список пациентов стал компактнее: рядом видны последний приём, повторная явка, больничный и статус записей. Поиск и скрытые фильтры сохраняют прежние правила. Лучшее совпадение можно открыть сразу; остальные найденные приёмы раскрываются по нажатию. Во время заполнения закреплены ФИО, дата, статус записи и сохранения; внизу доступны переходы между разделами, а на вкладке «Запись» — формирование, копирование, скачивание и отметка проверки врачом.

В 0.8.2 в разделе «Пациенты» оставлена одна строка поиска без выбора параметра. Введите фамилию, жалобу, диагноз, дату, номер больничного или несколько ключевых слов. Поиск охватывает всю историю. Сначала показаны результаты с большим числом совпавших слов, затем учитываются точность совпадения и поле: ФИО и коды имеют преимущество при равном качестве. Точное слово выше его части, часть слова выше небольшой опечатки. У результата видны причина совпадения и фрагмент подходящей записи; найденный приём можно сразу открыть.

Распознаются регистр, ё/е, несколько форматов даты и одна опечатка в словах от 5 букв. Номера и даты приблизительно не подбираются. Для нескольких ключевых слов допускается совпадение не менее двух третей слов с явной пометкой; все части запроса, содержащие цифры, обязательны. Слова из разных приёмов не складываются в полное совпадение. Рубрика и фильтры ограничивают результаты. Пока введён запрос, основной порядок — по совпадению; при очистке строки возвращается выбранная сортировка. Панель фильтров по-прежнему изначально скрыта.

Изменения предыдущих версий (выбор поля поиска из0.8.1 заменён единой строкой):

В 0.8.1 фильтры в разделе «Пациенты» изначально скрыты. Нажмите «Фильтры», чтобы показать условия явки, статуса записей, сортировки и дат. При сворачивании выбранные условия продолжают действовать и видны над списком. «Сбросить фильтры и поиск» очищает их внутри текущей рубрики.

Поиск работает по всей истории: ФИО, код пациента или приёма, дата приёма, повторная явка, номер выданного больничного, текст анамнеза/осмотра/диагноза/рекомендаций и ручной записи. Выберите «Все параметры» либо конкретное поле в «Искать по». Даты можно вводить как 19.10.2026, 2026-10-19 или 19 октября 2026. Несколько слов применяются совместно к одному приёму с ФИО/кодом пациента. Поиск включает состоявшиеся явки; фильтры явки, как прежде, учитывают незавершённые назначения. Под совпавшим пациентом доступны кнопки открытия найденных приёмов.

В 0.8.0 раздел «Пациенты» содержит рубрики «Все пациенты», «На больничном», «Повторная явка» и «Незавершённые записи». Рубрики пересекаются; счётчики показывают число пациентов до фильтрации. Поиск работает по ФИО, коду пациента и номеру выданного ЛН. Фильтры явки, последнего приёма и статуса записи можно сочетать. Сортировка — по явке, окончанию действующего ЛН, последнему приёму или ФИО. «Сбросить фильтры» очищает условия внутри выбранной рубрики.

В рубрике «На больничном» показаны пациенты с действующим по введённым датам ЛН либо неполным периодом. Отдельные условия: действует по датам, заканчивается сегодня, за ближайшие 3 дня (сегодня и следующие 2), период не указан полностью. Неполный период помечен как требующий уточнения и не считается действующим. Программа отражает сведения из приёмов и не подтверждает открытие или закрытие документа. Прошедшие и ещё не начавшиеся полные периоды доступны через «Все пациенты» и поиск номера.

В 0.7.2 в списке пациентов рядом с последним приёмом показана повторная явка. Сначала идут пациенты с сегодняшней или будущей датой, от ближайшей к дальней. Если назначений несколько, берётся ближайшее предстоящее, не отмеченное как состоявшееся. Прошедшие незакрытые даты отмечены отдельно; пациенты только с ними идут следом, без назначений — в конце. Список обновляется при смене дня, поиск сохраняет порядок.

В 0.7.1 меню упорядочено: «Обзор» → «Пациенты» → «Новый пациент» → «Текущий приём» → «Повторные приёмы» → «Модули» → «Помощь и данные» → «Проверить обновления». Пункт текущего приёма появляется после открытия записи. Дата и время в верхней панели увеличены.

В 0.7 добавлены список повторных приёмов и статусы записи «Черновик» / «Проверено врачом». ФИО доступно в начале вкладки «Приём» и в карточке; имя общее для всех приёмов пациента. Используйте только вымышленные ФИО. Постоянные UI-тесты проверяют работу в двух окнах, отсутствие лишнего приёма и видимость предупреждения при конфликте.

Используйте только демонстрационные, вымышленные данные. Клинические протоколы и нормативные формы Беларуси не реализованы. Программа не назначает лечение и не оформляет листки нетрудоспособности.

Текущая разработка относится к поликлиническому режиму. Стационарный режим запланирован отдельно и пока не доступен.

## Запуск

Скачайте исходники репозитория через Code → Download ZIP, распакуйте и откройте `medassist/Start-MedAssist.cmd`. Установленный Edge или Chrome откроет приложение в отдельном окне. Дополнительные библиотеки и интернет для приёма не нужны.

Один раз откройте `medassist/Pin-MedAssist.cmd`: он создаст ярлыки `MedAssist` и `MedAssist Update` на рабочем столе. Сохраняйте постоянную папку приложения.

## Карточка и повторный приём

Нажмите «Новый пациент», заполните первый приём и откройте «Карточка и история пациента». ФИО пациента можно заполнить сразу на вкладке «Приём» или в карточке. В разделе «Пациенты» можно искать карточки и открывать прежние посещения. Для повтора нажмите «Повторный приём», выберите исходную запись и отметьте сведения для переноса. Без отметок всё останется пустым; отмена не создаёт запись.

Приёмы версий до 0.6 автоматически получают отдельные карточки; карточки и связи из 0.6 сохраняются. Все прежние записи получают статус «Черновик». Исходные сохранения и ручные тексты остаются нетронутыми. JSON содержит карточки, приёмы, статусы и связи повторов; новая копия требует версии 0.7+.

## Список повторных приёмов

Дата в конце вкладки «Запись» появляется в разделе «Повторные приёмы». Фильтры: «Сегодня», «Ближайшие» (все будущие даты), «Дата прошла» и «Состоявшиеся». Используется местная дата компьютера. Прошедшая дата сама по себе не означает неявку.

Из списка откройте карточку или нажмите «Начать повторный приём». Новая запись создаётся после подтверждения переноса препаратов, аллергий и заболеваний; без отметок эти поля пусты. После создания кнопка «Открыть начатый приём» открывает связанную запись без повторного создания.

Факт приёма отмечайте отдельно кнопкой «Отметить: состоялся» с подтверждением. Создание записи не ставит эту отметку автоматически. «Вернуть в план» снимает отметку, сохраняя запись. Изменение или удаление назначенной даты в исходном приёме сбрасывает отметку и связь; ранее созданный приём остаётся в истории пациента.

## Статус записи

Новые и прежние записи имеют начальный статус «Черновик». На вкладке «Запись» проверьте текст, нажмите «Отметить: проверено врачом» и подтвердите действие. Текст должен быть непустым, а поля — без ошибок технической валидации. Программа не проверяет медицинское содержание; это личная отметка, не электронная подпись.

Изменение полей, текста, повторная генерация и применение нормального осмотра возвращают запись в черновики. Изменение ФИО снимает проверку связанных записей этого пациента. Явное действие «Вернуть в черновики» также сохраняет текст. Фильтр «Черновики» на главной показывает незавершённые записи; рядом доступны «Все» и «Проверено врачом». Статус записи и отметка состоявшегося приёма независимы.

## Работа с осмотром

В новом приёме поля пусты. Кнопка «Осмотр без особенностей» заполняет 27 вариантов по нажатию. Любой пункт можно изменить или очистить. При замене отличающихся результатов требуется подтверждение. Показатели, уточнения и ручной черновик сохраняются; выбранные признаки проверяет врач.

Кнопка у названия каждого раздела заполняет только его признаки. Рядом с массой и ростом автоматически вычисляется ИМТ; заполненный результат включается в новый черновик. Дата повторного приёма расположена после больничного и завершает запись.

## Обновление

**Однократный переход с 0.6 или более ранней версии на 0.7:** прежний обновлятор не поддерживает схему данных 4. Сохраните JSON-копию, закройте приложение и окна обновления, сохраните старый `medassist/updater/Update-Core.ps1`, затем замените только этот файл версией из этого репозитория в той же папке установленной программы. Новый файл принимает схемы 2/3/4. После этого используйте обычную кнопку обновления. Не переносите папку `app`, не очищайте данные браузера. Для новой установки из актуального архива совместимый обновлятор уже включён. Обычный пакет обновляет только `app` и не доставляет эту замену автоматически.


Нажмите **«Проверить обновления»** в левом меню. Браузер может попросить разрешить открытие окна обновлятора. После проверки новая версия устанавливается по подтверждению. `MedAssist Update` и `medassist/Update-MedAssist.cmd` остаются запасным способом. Перед установкой сохраните JSON через «Помощь и данные» → «Резервная копия» и закройте окна приложения.

Кнопка подключается при запуске через `Start-MedAssist.cmd`. Для прежних установок 0.3/0.4 нужны два новых файла: `Start-MedAssist.cmd` и `updater/Register-UpdateLink.ps1`, размещённые в той же папке программы. Обычный пакет обновления не заменяет файлы запуска. [Однократное подключение и блокировка скачанных файлов Windows](medassist/START-HERE.txt).

Пакет берётся из `release/medassist-update.json` этого репозитория. Повторно скачивать архив и распаковывать его вручную не нужно. Обновление заменяет только файлы `medassist/app`, сохраняя прежний адрес локального приложения и копию старых файлов. После прерывания повторный запуск обновления восстанавливает целостную папку.

Записи находятся в локальном хранилище браузера. Пакет обновления не содержит приёмов, и обновлятор не отправляет их на сервер. Перед сменой папки или браузера нужен экспорт JSON. Полная инструкция: [START-HERE.txt](medassist/START-HERE.txt).

Сохранение версии 0.7 использует ключ `medassist.demo.v4`. При его отсутствии чтение идёт последовательно из `v3`, `v2`, `v1`; исходные ключи не меняются. Миграция при чтении ничего не записывает, последующее сохранение создаёт отдельные данные v4. Импорт поддерживает схемы 1/2/3/4.

## Проверки и устройство

Приложение: HTML/CSS/JavaScript без сторонних библиотек. Обновлятор: встроенный Windows PowerShell 5.1. Он проверяет HTTPS, размер, версии, список файлов и SHA-256; подпись издателя не реализована. Политики Windows не меняются. Если система запрещает сценарий, обычный запуск программы остаётся доступен.

Обязательные проверки из корня репозитория, включая постоянные сценарии интерфейса:

```powershell
$env:MEDASSIST_PLAYWRIGHT = 'C:\tools\node_modules\playwright'
node --test medassist/tests/core.test.cjs medassist/tests/ui-patient.test.cjs medassist/tests/ui-workflow.test.cjs
powershell.exe -NoProfile -File medassist/tests/update.test.ps1
powershell.exe -NoProfile -File medassist/tests/update-link.test.ps1
```

В примере замените путь на уже установленную библиотеку Playwright. Если она доступна через обычный Node module resolution, переменная не нужна. Тест использует установленный Microsoft Edge и отдельный временный контекст браузера; пользовательский профиль не открывает. Библиотеки и браузеры автоматически не устанавливаются. Без библиотеки/браузера проверка завершается ошибкой, а не пропускается. Необязательные переменные: MEDASSIST_BROWSER — полный путь к исполняемому файлу совместимого браузера; MEDASSIST_APP_ROOT — папка app проверяемой установки.

Тесты карточек проверяют конфликт двух окон, отсутствие записи при конфликте, фактическую видимость предупреждения поверх страницы, явную повторную загрузку и создание приёма после подтверждения. Также проверяются общее ФИО карточки и приёмов, изоляция пациентов, перезагрузка, сохранность ручного текста и длинное имя на узком экране. Сценарии workflow проверяют списки повторных дат, явные отметки, связанную запись без дубликатов, проверку текста и возврат в черновики при изменениях. Результаты выпуска перечислены в CHECKS.txt.

Node нужен только разработчику для проверок и сборки пакета обновления.

Совместимый обновлятор формата 1 принимает схемы данных 2, 3 и 4. Изменение обновлятора или схемы данных требует отдельного решения о совместимости. Выпуск 0.7 не добавляет зависимостей или новых клинических правил.
