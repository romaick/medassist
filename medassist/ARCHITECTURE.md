# МедАссистент 0.4: архитектура

Локальное HTML/CSS/JavaScript-приложение открывается в окне установленного Edge или Chrome. Сервер, установка библиотек и подключение к МИС не требуются. Рабочие функции не обращаются к внешней сети.

## Слои

| Файл | Назначение |
| --- | --- |
| app/exam-options.js | Каталог 27 отдельных полей осмотра: значения, подписи и фразы |
| app/core.js | Модель, проверки, генератор, импорт v1/v2 |
| app/storage.js | Локальное сохранение, чтение старого ключа, явные ошибки |
| app/app.js, index.html, styles.css | Формы, главная, редактор, скачивание и восстановление |
| app/modules.js | Реестр будущих модулей |
| Start-MedAssist.cmd | Запуск страницы в Edge, затем Chrome или браузере по умолчанию |

Каталог и ядро предоставляют браузерные globals и CommonJS для тестов. Справочные материалы не загружаются во время работы. Терминология и пределы проверки — в [EXAM-SOURCES.md](EXAM-SOURCES.md).

## Модель версии 2

Основные поля: id, createdAt, updatedAt, visitDate, age, sex, reason. Разделы: history, exam, examSelections, vitals, assessment, draft. Пользовательские значения — строки.

- history: жалобы, начало, течение, заболевания/операции, постоянные препараты, аллергии, дополнительный анамнез.
- examSelections: отдельные значения из каталога. Ритм и звучность тонов независимы; новые поля пусты.
- exam: уточнения и исходные описания 0.1. Не преобразуются в признаки автоматически. Уточнения включаются вместе с выбором; согласованность проверяет врач.
- vitals: измерения без клинической интерпретации.
- assessment.summary: диагноз; plan: рекомендации; returnVisitDate: дата повторного приёма.
- assessment.sickLeaveIssued: пусто/no/yes; sickLeaveNumber: ручной номер; sickLeaveFrom/sickLeaveTo: необязательные даты.
- assessment.followUp: старый свободный текст наблюдения 0.1. Сохраняется дословно; в новой пустой форме не показывается. Можно изменить или очистить после переноса нужного.
- draft: редактируемый текст, дата генерации и отпечаток исходных полей. Форма не перезаписывает текст; повторная генерация требует подтверждения.

Пустые дополнительный анамнез, другие данные осмотра, рекомендации и повторный приём не создают строк. Больничный отражается только при yes: отметка, заполненный номер, затем даты. При no детали сохраняются, но исключаются из текста. Программа не оформляет документ и не определяет срок.

## Совместимость

JSON содержит format=medassist-demo, schemaVersion=2, exportedAt, encounters. Импорт принимает версии 1 и 2, проверяет структуру, значения, даты, длины и уникальность ID.

Импорт v1 добавляет пустые поля и сохраняет все прежние тексты и ручной черновик. Отпечаток старого черновика не переписывается: может появиться сообщение о необходимости сверки. Старое наблюдение не превращается в дату. Новая копия v2 не подходит программе 0.1.

Ключ v2 — medassist.demo.v2. При его отсутствии читается medassist.demo.v1; чтение не записывает данные. Сохранение/восстановление меняет только v2. Повреждённое сохранение блокирует автоматическую запись. Изменения в другом окне приостанавливают сохранение текущего окна.

## Ограничения и расширение

Для file: URL поведение localStorage зависит от браузера. Перед обновлением, перемещением папки, сменой профиля или очисткой браузера нужен JSON-экспорт. Очистка списка 0.2 не удаляет ключ 0.1 и файлы на диске.

Только вымышленные данные. Нет шифрования, авторизации, аудита, клинических рекомендаций, МИС и нормативных форм Беларуси. Соответствие медицинской эксплуатации не оценивалось. Каталог осмотра — инструмент записи, а не полный стандарт обследования.

Будущим модулям нужны отдельные контракты, версии, проверки и источники. Официальным документам — проверка применимости, редакции и даты.

Для разработчика из папки приложения: node --test tests/core.test.cjs. Node нужен только для тестов; сторонних зависимостей у приложения нет. Результаты поставки — CHECKS.txt.

- Требования пользователя и исходный код определяют поведение.
- [MDN: localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) — ограничения file: URL.
- [Microsoft Learn: PWA development](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/) и [PWA in Edge](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/ux) изучены при выборе оболочки; текущая поставка не установлена как PWA.
- Медицинские источники, точные ссылки, объём проверки и непроверенные утверждения перечислены в EXAM-SOURCES.md.


## Явный шаблон осмотра

NORMAL_SELECTIONS задаёт именованное соответствие всех 27 полей каталога. Кнопка меняет только examSelections по явному нажатию; отклоняющиеся непустые значения заменяются после подтверждения. Показатели, свободные описания и ручной черновик сохраняются. Пустая новая форма не заполняется автоматически. Версия данных остаётся 2.

## Независимое интернет-обновление

Отдельный Update-MedAssist.cmd запускает Windows PowerShell 5.1 и окно обновления. update-channel.json содержит HTTPS-адрес опубликованного пакета. Адрес канала: https://raw.githubusercontent.com/romaick/medassist/main/release/medassist-update.json. Пользователь явно разрешил создание публичного репозитория и загрузку программы. Pin-MedAssist.cmd создаёт два ярлыка на рабочем столе, не заменяя ярлыки, ведущие в другую папку. Политики выполнения PowerShell не меняются.

Пакет medassist-update формата 1 содержит версию x.y.z, dataSchemaVersion=2 и ровно девять разрешённых файлов app. Каждый файл представлен Base64 и SHA-256; version.json должен совпадать с пакетом. HTTPS удостоверяет сервер при стандартной проверке сертификата; хеши выявляют повреждение и несогласованность, но не заменяют цифровую подпись издателя. Доверие к каналу обновления означает доверие опубликованному коду.

Пакет не содержит приёмы, настройки браузера, секреты, тестовые профили или файлы проекта sources. Скрипт обновления не читает хранилище браузера и не отправляет данные приёмов. Запрещены HTTP, перенаправления, произвольные пути и лишние файлы. Проверка и подготовка выполняются до замены; старая папка сохраняется, журнал позволяет восстановить прерванную замену. Два обновления одновременно блокируются. Путь app/index.html не меняется; фактическая сохранность данных проверяется в том же профиле Edge.

Пакет обновляет только app: изменение оболочки или обновлятора потребует отдельной поставки. Во время замены окна приложения должны быть закрыты. Онлайн-версия не создаёт новые функции сама: после публикации следующего проверенного выпуска пользователь получает его без участия чата.

Источники технических решений: [GitHub REST contents](https://docs.github.com/en/rest/repos/contents) — размещение файла и адрес raw; [Microsoft HttpClientHandler.AllowAutoRedirect](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpclienthandler.allowautoredirect?view=netframework-4.8.1) — управление перенаправлениями. Цифровая подпись издателя не реализована. Результат проверки сетевого канала фиксируется отдельно. Результаты локальных проверок — CHECKS.txt.

## Поликлинический режим и версия 0.4.0

Пользователь определил два будущих режима: поликлинический и стационарный. Текущие формы и генератор относятся к поликлиническому режиму, что явно показано в интерфейсе. Стационарный режим не реализован. Его набор документов, жизненный цикл госпитализации и разделение данных будут определены отдельным контрактом до реализации; фиктивный переключатель и неизвестные клинические правила не добавляются.

Кнопка у каждого раздела осмотра выбирает нормальные значения только его полей из существующего каталога. Подтверждение зависит только от отклонений внутри выбранного раздела. Уточнения, измерения, другие разделы и ручной черновик сохраняются; общая кнопка остаётся доступна.

calculateBmi(weightKg, heightCm) вычисляет массу / (рост / 100)² и возвращает строку с одним десятичным знаком и запятой. Значение показывается рядом с массой/ростом и включается в новый черновик после роста. Оно выводится из исходных измерений, отдельного поля в JSON нет: схема остаётся 2. Пустые, некорректные, неположительные и нечисловые результаты не отображаются, как и крайние значения, округляющиеся до нуля или требующие экспоненциальной записи. Автоматическая клиническая классификация не выполняется.

Дата повторного приёма — последнее поле раздела «Запись» и последняя строка нового черновика, после больничного и старого свободного наблюдения. Пустая дата не выводится. Сохранённые ручные черновики не меняются без повторной генерации.
