# МедАссистент: руководство для разработчика и ИИ-агента

Этот файл описывает устройство и правила, которые не зависят от компьютера. Состояние конкретной установки, пути и журнал работы хранятся вне репозитория: в `PROJECT-CONTEXT.md` и `TASKS.md` в корне локального проекта. История изменений по версиям — в `README.md`, `ARCHITECTURE.md` и `CHECKS.txt`; при расхождении верно описание более новой версии.

## Что это

Офлайн-прототип личного помощника врача первичного звена в Беларуси для Windows: приём, анамнез, осмотр, диагнозы по МКБ-10, черновик врачебной записи, анализы, больничные, повторные явки. HTML/CSS/JavaScript без сторонних библиотек, открывается в Edge или Chrome отдельным окном через `Start-MedAssist.cmd`. Сервер, Node.js и интернет для работы не нужны. Данные хранятся в localStorage браузера без шифрования. Только вымышленные данные: работа с реальными пациентами и нормативное соответствие не подтверждены.

Режимы: при запуске экран выбора «Поликлиника» / «Стационар» / «Модули» (с 0.24.0). Реализован только поликлинический режим. «Стационар» показан с пометкой «В работе» и заблокирован.

## Данные и совместимость

- Основное хранилище: `medassist.demo.v4`. Прежние ключи v1–v3 читаются и не перезаписываются. Отметка резервной копии: `medassist.backup-info.v1`.
- Формат записи: `medassist.record-format.v1`. В резервную копию не входит.
- Выбранный раздел окна: sessionStorage `medassist.session.area` (`polyclinic` или `modules`). Перезагрузка окна сохраняет раздел, новое окно начинается с выбора.
- Схема данных 4. Новые необязательные поля добавляются без смены схемы. Резервная копия с новыми полями требует соответствующей версии, это указывается в README и справке.
- Неизвестные данные молча не отбрасываются. Повреждённое сохранение блокирует запись и показывается пользователю.
- Ключи хранилища, папку запуска и формат данных без необходимости не менять.

## Поведение, которое нельзя ломать

- Пустая новая форма не создаёт карточку. Перезапись более новых данных другого окна блокируется, предупреждение видно.
- Ручной текст черновика не переписывается молча. Повторная генерация учитывает ручные правки. Существенные правки снимают отметку «Проверено врачом».
- Завершение приёма, проверка врачом и отметка состоявшейся явки — отдельные явные действия.
- Перенос препаратов, аллергий, заболеваний и назначений в повторный приём — только по явному выбору и подтверждению врача.
- Пустой осмотр не означает норму. Пустые необязательные поля не попадают в черновик. Повторный приём — в самом конце записи, после больничного.
- Больничные: календарные дни включительно, пересечения считаются один раз (19–23 + 23–27 = 9 дней, текущий отрезок 5). Разные случаи и номера не объединяются. Расчёта оплаты и нормативных правил нет.
- Программа не ставит диагноз, не придумывает соответствия кодам МКБ и не выдаёт шаблоны за утверждённые бланки Беларуси.
- «Мои сокращения» убраны из интерфейса (0.25.0) по решению пользователя: ни окна, ни кнопок, ни Ctrl+Пробел. Сохранённые фразы `bundle.shortcuts` нельзя терять: они проходят через сохранение, резервную копию и восстановление. Не возвращать интерфейс без отдельного задания.
- Сверка анализов «Из текста» заблокирована с пометкой «В работе» (8 UI-сценариев пропущены). Фото-OCR не подключён. Не включать без отдельного задания.

## Проверки

Полный обязательный набор — команды в `README.md`, раздел «Проверки и устройство»: один вызов `node --test` со списком файлов и два теста PowerShell (`update.test.ps1`, `update-link.test.ps1`).

- `MEDASSIST_PLAYWRIGHT` — путь к установленной библиотеке Playwright, если она не находится обычным поиском модулей.
- `MEDASSIST_BROWSER` — путь к браузеру. По умолчанию используется установленный Edge (`channel: msedge`). В Linux проверки работают с Chromium из Playwright.
- `MEDASSIST_APP_ROOT` — папка `app` проверяемой установки, например установленной копии после обновления.
- Каждый UI-тест открывает отдельный офлайн-контекст браузера с вымышленными данными. Пользовательский профиль не используется.
- После загрузки страницы показывается экран выбора: тесты входят в поликлинику через `enterPolyclinic` из `tests/ui-actions.cjs`. Новые UI-тесты делают так же. Новый тестовый файл добавляется в команду README.
- Сначала прицельные тесты по изменению, затем полный набор один раз. В отчёте указываются команды, числа и длительности.

## Выпуск и установка

1. Версия меняется в `app/version.json`, в заголовке `app/index.html` и в строках «Версия» и «Прототип» в `app/app.js`. Затем в шапках документов.
2. Пакет собирает `node release/build-update.cjs`. Скрипт заново генерирует сжатые каталоги в `app/modules.js`; другая версия Node может дать другие байты при том же содержимом. Если содержимое не менялось, верните прежний `modules.js` и упакуйте без пересборки. Пакет не больше 2 MiB, SHA-256 всех 9 файлов сверяются с исходниками.
3. Полный набор проверок на состоянии выпуска.
4. Публикация одним коммитом «Release X.Y.Z: …» и только fast-forward в `main` репозитория romaick/medassist. Канал обновлений читает `release/medassist-update.json` из `main`, поэтому push в `main` и есть выпуск. Публикация — только с явного разрешения пользователя.
5. Установка штатным обновлятором (кнопка «Проверить обновления» или `Update-MedAssist.cmd`). Обновлятор заменяет только 9 файлов `app`, прежние сохраняет в `update-work`. Более старую версию он не ставит, ту же версию считает актуальной. Номер версии каждого выпуска должен быть больше предыдущего.
6. После установки: сверить SHA установленных файлов, прогнать UI-тесты с `MEDASSIST_APP_ROOT`, открыть программу обычным ярлыком.

## Подводные камни

- В исходниках смешанные окончания строк (часть строк CRLF). Правьте точечно и проверяйте `git diff --stat`: изменение тысяч строк означает переписанные окончания.
- Все страницы, открытые из файлов (`file://`), в одном профиле браузера, скорее всего, делят localStorage. Не открывайте `index.html` из исходников в рабочем профиле врача: копия из исходников увидит рабочие записи. Проверяйте в отдельном профиле.
- `Start-MedAssist.cmd` передаёт в адресе `#updates=…` для кнопки обновления. Хэш адреса приложение для другого не использует.
- Документы README, ARCHITECTURE, CHECKS и START-HERE написаны слоями по версиям, новое сверху. Перед правкой поведения ищите в них все упоминания затронутой функции.
