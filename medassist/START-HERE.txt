МЕДАССИСТЕНТ 0.7.2 — ОФЛАЙН-ПРОТОТИП ДЛЯ WINDOWS

В 0.7.2: в списке пациентов показана ближайшая повторная явка.
Сначала пациенты с сегодняшней/будущей датой от ближайшей к дальней,
затем только с прошедшей незакрытой датой, затем без назначений.
Состоявшиеся приёмы не учитываются. Последний приём остаётся виден.

В 0.7: список повторных приёмов и статусы «Черновик» / «Проверено врачом».
ФИО пациента вводится первым полем на вкладке «Приём»
или в карточке. Это одно общее поле для всех приёмов этого пациента.
Используйте только вымышленные фамилию, имя и отчество.
ФИО сохраняется автоматически; прежние черновики не переписываются.

Карточки вымышленных пациентов содержат историю приёмов.
Новый пациент создаётся вместе с первым приёмом. В карточке можно
задать условное имя. «Повторный приём» позволяет выбрать исходную запись
и отметить отдельно препараты, аллергии, заболевания. Перенос происходит
только после нажатия «Создать приём». Без отметок поля остаются пустыми.
Возраст, пол, жалобы, осмотр и заключение заполните заново.
Старые приёмы получают отдельные карточки; ручные черновики сохраняются.
Новые JSON-копии содержат карточки, статусы и связи повторных приёмов.
Для открытия такой копии нужна версия 0.7 и новее.

Используйте только вымышленные данные.
Сейчас разрабатывается поликлинический режим.
Стационарный режим предусмотрен отдельно и пока не реализован.

ЗАПУСК И ЯРЛЫКИ

Откройте Start-MedAssist.cmd из этой папки.
Один раз запустите Pin-MedAssist.cmd — на рабочем столе появятся:
  MedAssist — открыть приложение;
  MedAssist Update — проверить интернет-обновление.

Ярлыки используют эту же папку. Не переносите и не удаляйте её.
Для обычной работы интернет не нужен. Приложение открывается в Edge;
если он отсутствует, используется Chrome или браузер по умолчанию.

ОДНОКРАТНЫЙ ПЕРЕХОД С 0.6 ИЛИ БОЛЕЕ РАННЕЙ ВЕРСИИ НА 0.7

Обновлятор версии 0.6 не поддерживает новую схему данных и не установит 0.7.
Сначала сохраните JSON-копию, закройте МедАссистент и окно обновления.
Сохраните копию updater/Update-Core.ps1 и замените только этот файл
версией из проекта romaick/medassist в той же папке программы.
Затем используйте обычную кнопку обновления. Папку приложения
не переносите, данные браузера не очищайте. Для новой установки
из архива совместимый обновлятор уже включён.
Новый Update-Core.ps1 поддерживает схемы данных 2, 3 и 4.
Обычный интернет-пакет не заменяет этот файл автоматически.

ОБНОВЛЕНИЕ ЧЕРЕЗ ИНТЕРНЕТ

Канал: https://github.com/romaick/medassist
Адрес обновления уже указан в update-channel.json.
Для получения следующей опубликованной версии:

1. Нажмите «Проверить обновления» в левом меню программы.
   Если браузер запросит разрешение открыть обновлятор, нажмите «Открыть».
   Запасной способ — MedAssist Update или Update-MedAssist.cmd.
2. Программа проверит постоянный интернет-адрес и загрузит пакет.
3. Если версия новая, сохраните JSON через «Помощь и данные» →
   «Резервная копия», затем закройте окна МедАссистента.
4. Подтвердите установку в окне обновления.
5. После сообщения об успехе откройте MedAssist обычным ярлыком.

Скачивать архив по ссылке и распаковывать его вручную больше не нужно.
Программа заменяет только свою папку app. Записи остаются в прежнем
браузере; адрес локального приложения сохраняется. Сам обновлятор,
ярлыки и настройки канала не заменяются загруженным пакетом.
Проверка обновления не отправляет записи на сервер.

Если сети нет, закройте сообщение и пользуйтесь установленной версией.
Если установка прервалась, повторно запустите Update-MedAssist.cmd:
он сначала проверит и восстановит незавершённую замену файлов.
Прежняя версия файлов остаётся в update-work. Это копия программы,
она НЕ заменяет резервную копию JSON с приёмами.

Обновлятор использует встроенный Windows PowerShell 5.1 без установки
библиотек. Если Windows запрещает запуск сценария, не меняйте политики
безопасности: обычный Start-MedAssist.cmd продолжает работать.
Сообщите точный текст ошибки, чтобы подобрать разрешённый запуск.

КНОПКА «ПРОВЕРИТЬ ОБНОВЛЕНИЯ»

Запускайте программу через обычный ярлык MedAssist или Start-MedAssist.cmd.
При запуске подключается кнопка именно этой папки программы. Она открывает
отдельное окно обновления. В самой форме приёма интернет не используется.
При открытии app/index.html напрямую кнопка покажет инструкцию запуска.

Для установок 0.3/0.4 нужна однократная установка новых файлов запуска:
1. Сохраните JSON и закройте окна приложения.
2. Скачайте актуальные исходники из github.com/romaick/medassist.
3. Скопируйте новый Start-MedAssist.cmd в вашу прежнюю папку medassist,
   а updater/Register-UpdateLink.ps1 — в её подпапку updater.
   Путь app/index.html и папку с вашей рабочей программой сохраняйте.
4. Замените Update-Core.ps1 по инструкции перехода на 0.7 выше,
   затем откройте Start-MedAssist.cmd и проверьте обновления.

Обычный интернет-пакет заменяет только app. Он не доставляет новые файлы
запуска автоматически. После однократного подключения дальнейшие версии
интерфейса можно проверять кнопкой из приложения.

Если Windows блокирует файлы из скачанного ZIP, сначала убедитесь, что
архив получен из romaick/medassist. В свойствах файлов Register-UpdateLink.ps1,
Update-MedAssist.ps1 и Update-Core.ps1 в папке updater может быть пункт
«Разблокировать». Разрешайте только эти проверенные файлы. Общие политики
PowerShell менять не требуется. Если пункта нет или запуск запрещён
администратором, сохраните точный текст ошибки для разбора.

ОДНОКРАТНЫЙ ПЕРЕНОС ИЗ СКАЧАННОЙ РАНЕЕ ПАПКИ

Если вы работали в другой папке версии 0.1 или 0.2:
1. В прежней программе сохраните JSON: «Помощь и данные» →
   «Резервная копия».
2. Откройте Start-MedAssist.cmd из этой постоянной папки.
3. «Помощь и данные» → «Восстановить» → выберите JSON.
4. Проверьте список и ручные черновики. Дальше пользуйтесь новым ярлыком.

Если это та же папка и браузер, перенос не нужен. Новая программа
сохраняет формат данных версии 4 и поддерживает импорт версий 1, 2 и 3.
Сначала читается сохранение версии 4; при его отсутствии — 3, затем 2 и 1.
Чтение старых записей не меняет исходные сохранения. При последующем
сохранении создаётся отдельное хранилище версии 4. Старые записи
появляются со статусом «Черновик», их тексты остаются прежними.

ДЕМОНСТРАЦИОННЫЙ ПРИЁМ

1. «Новый пациент» — новая карточка и пустой приём.
   «Открыть пример» — вымышленный пример.
2. В «Анамнезе» внесите известные сведения. Препараты обозначены как
   «Принимаемые препараты на постоянной основе».
3. В «Осмотре» выбирайте оценённые признаки. Разделы раскрываются по
   нажатию на название; есть «Раскрыть все разделы».
   Ритм и звучность тонов сердца задаются независимо. Ни один результат
   не выбран заранее. «Осмотр без особенностей» по вашему нажатию
   заполнит 27 вариантов. Любой пункт можно изменить или очистить.
   При замене уже выбранного отклонения потребуется подтверждение.
   Проверьте все признаки; ваши уточнения и измерения сохраняются.
   Кнопка рядом с названием раздела заполняет только этот раздел.
   Общая кнопка заполняет весь осмотр. Для особенностей используйте уточнение.
   Рядом с массой (кг) и ростом (см) автоматически отображается ИМТ.
   Пустые, некорректные и нулевые значения не дают результата.
   Рассчитанный ИМТ попадает в новый черновик после роста.
4. В «Записи» заполните диагноз, при необходимости рекомендации и дату
   повторного приёма.
5. Для больничного выберите «Выдан». Ниже появятся ручной номер и даты.
   Номер расположен перед датами. Эти сведения необязательны.
   «Повторный приём» находится после больничного и завершает черновик.
6. «Сформировать черновик» → проверить и отредактировать.
   «Скачать .txt» сохраняет текущий текст; «Копировать» копирует его.
7. После проверки текста нажмите «Отметить: проверено врачом»
   и подтвердите действие. Пустой текст или ошибки заполнения
   не позволяют поставить отметку. Программа не оценивает
   медицинское содержание; это личная отметка, не электронная подпись.

Пустые дополнительный анамнез, другие данные осмотра, рекомендации
и повторный приём не упоминаются. Если больничный не выдавался или
отметка пуста, строка о нём, номер и даты не включаются.
Срок не рассчитывается. Это отметка в тексте, не оформление документа.

Старые описания видны в «Уточнение или сохранённое описание» и попадут
в текст вместе с выбранными признаками: проверьте согласованность.
Старое свободное наблюдение видно отдельно в «Записи». Перенесите
нужное в рекомендации/дату и очистите прежний текст, если он не нужен.

Форма не перезаписывает ручной черновик. Для применения изменений
сформируйте его заново и подтвердите замену. Нужные правки перед этим
можно скачать в .txt.

ПОВТОРНЫЕ ПРИЁМЫ

Дата в конце вкладки «Запись» попадает в раздел «Повторные приёмы»
левого меню. В нём четыре списка:
  Сегодня — назначено на текущую местную дату компьютера;
  Ближайшие — все будущие даты;
  Дата прошла — назначенная дата уже наступила и закончилась;
  Состоявшиеся — даты с вашей отметкой о состоявшемся приёме.

Прошедшая дата сама по себе не означает неявку. Откройте карточку
или нажмите «Начать повторный приём». Выберите сведения для переноса
и подтвердите создание. Если связанная запись уже есть, кнопка
«Открыть начатый приём» откроет её без создания ещё одного приёма.

После фактического приёма отдельно нажмите «Отметить: состоялся»
и подтвердите. Создание записи не ставит эту отметку автоматически.
«Вернуть в план» снимает отметку, сохраняя связанную запись.

Изменение или удаление назначенной даты в исходном приёме сбрасывает
отметку и связь с повторным приёмом. Его запись остаётся в истории
пациента; новый план больше не открывает её как свой связанный приём.

СТАТУС ВРАЧЕБНОЙ ЗАПИСИ

Новые и прежние записи начинают работу со статусом «Черновик».
На главной выберите фильтр «Черновики», чтобы увидеть незавершённые.
Фильтры «Все» и «Проверено врачом» переключают рабочий список.

Правки полей, текста, повторная генерация и применение кнопки
«Осмотр без особенностей» снимают отметку проверки. Изменение ФИО
возвращает в черновики проверенные записи этого пациента.
После исправлений проверьте запись и подтвердите её снова.
Можно также явно нажать «Вернуть в черновики»; текст сохранится.

«Проверено врачом» и «Состоялся» — независимые отметки. Подтверждение
факта приёма не проверяет запись, а проверка текста не завершает план.

СОХРАНЕНИЕ

Следите за статусом сохранения в приёме. При ошибке не закрывайте окно,
пока не сохраните нужные данные. JSON содержит формы и ручные черновики.
TXT — только одну запись, он не заменяет полную резервную копию.

Перед переносом папки, сменой браузера/профиля или очисткой браузера
скачайте JSON. Хранилище не лежит в папке приложения. Для локальных
файлов его поведение зависит от браузера.

Восстановление заменяет текущий список после подтверждения.
Чтобы сохранить оба набора, сначала скачайте текущую копию.
Повреждённый файл или неподдерживаемая версия не заменяют данные.

Очистка списка 0.7 не удаляет сохранения версий 1, 2 и 3
и скачанные файлы. При работе в двух окнах конфликт останавливает
сохранение; сначала явно загрузите актуальные данные по сообщению.

ОГРАНИЧЕНИЯ

Нет шифрования, авторизации и готовности к реальным медицинским данным.
Не вводите сведения о реальных пациентах. Диагноз и рекомендации
заполняет врач. Нет МИС, официальных форм и клинических протоколов.

Варианты осмотра — вспомогательные формулировки; это не утверждённая
единая форма Беларуси и не исчерпывающий стандарт обследования.
Источники и ограничения: EXAM-SOURCES.md.
Архитектура: ARCHITECTURE.md. Проверки: CHECKS.txt.
